Data Management
•Without data and the ability to process it an organization could 
not successfully complete most business activities
ถ้าองค์กร ไม่มีข้อมูลและความสามารถในการประมวลผลข้อมูล จะไม่สามารถ

• Record
• Collection of related data fields 
• เมื่อนำfields หลายๆ fields มาเรียงต่อกัน เรียกว่า record เช่น record ที่ 1 
เก็บ ชื่อ นามสกุล วันเดือนปีเกิด ของ นักเรียนคนที่ 1 เป็นต้น
• File
• Collection of related records 
• การเก็บrecords หลายๆrecords รวมกัน เรียกว่า แฟ้มข้อมูล (File) เช่น

500 คน เป็นต้น
• Database
• Collection of integrated and related files
• การจัดเก็บ File หลายๆ File ไว้ภายใต้ระบบเดียวกัน เรียกว่า ฐานข้อมูล หรือ 
Database เช่น เก็บแฟ้มข้อมูล นักเรียน อาจารย์ วิชาที่เปิดสอน เป็นต้น

Data Entities, Attributes, and Primary Keys
•Entity
• Generalized class of people, places, or things (objects) for which data is 
collected, stored, and maintained คน สถานที่ หรือ วัตถุ  ซึ่งเป็นข้อมูลที่ต้องการ

•Attribute
• Characteristic of an entity
•Data item
• Specific value of an attribute
•Primary key
• Field or set of fields that uniquely identifies the record

Data Modeling and Database Characteristics
•When building a database, an organization must consider: 
•Content: What data should be collected and at what cost? ข้อมูลใด
ที่ควรรวบรวมและมีค่าใช้จ่ายเท่าไร
•Access: What data should be provided to which users and when? 
ข้อมูลใดที่ควรให้กับผู้ใช้และเมื่อใด
•Logical structure: How should data be arranged so that it makes 
sense to a given user? ควรมีการจัดเรียงข้อมูลอย่างไรเพื่อให้เหมาะสมกับ
ผู้ใช้ที่ได้รับ
•Physical organization: Where should data be physically located? 
ข้อมูลควรอยู่ที่ใด

Data Modeling
•Building a database requires two types of designs
• Logical design
• Abstract model of how data should be structured and arranged to meet an 
organization’s information needs แบบจำลองนามธรรมของวิธีการจัดโครงสร้างข้อมูล
และจัดเรียงเพื่อให้สอดคล้องกับความต้องการข้อมูลขององค์กร
• Physical design
• Starts from the logical database design and fine-tunes it for performance and 
cost considerations เริ่มต้นจากการออกแบบฐานข้อมูลเชิงตรรกะ และปรับแต่งเพื่อการ
พิจารณาประสิทธิภาพและค่าใช้จ่าย โครงสร้างข้อมูลและการจัดเก็บวิธีการเข้าถึงข้อมูล 
รวมถึงการจัดการด้านระบบความ ปลอดภัย เพื่อให้ฐานข้อมูลท างานได้อย่างมีประสิทธิผล
มาก

Overview of Database Types
• Flat file
• Simple database program whose records have no relationship to one 
another คือ โปรแกรมฐานข้อมูลอย่างง่ายที่มีบันทึกไม่มีความสัมพันธ์ซึ่งกันและกัน
• Single user ผู้ใช้คนเดียว
• Only one person can use the database at a time สามารถใช้ฐานข้อมูลได้ครั้งละหนึ่ง
คนเท่านั้น
• Examples: Access, FileMaker 
• Multiple user
• Allows dozens or hundreds of people to access the same database system at 
the same time อนุญาตให้ผู้ใช้หลายสิบหรือหลายร้อยคนเข้าถึงระบบฐานข้อมูลเดียวกันใน
เวลาเดียวกัน
• Examples: Oracle, Sybase, and IBM

Creating and Modifying the Database
•Data definition language (DDL)
•Collection of instructions and commands used to define and describe 
data and relationships in a specific database ชุดคำสั่งและคำสั่งที่ใช้ เพื่อ
กำหนดและอธิบายข้อมูลและความสัมพันธ์ในฐานข้อมูล
•DDL เป็นส่วนหนึ่งของ SQL (Structured Query Language) ใช้สำหรับกำหนด
โครงสร้างของฐานข้อมูล เช่น การสร้างตาราง (CREATE), การแก้ไข (ALTER), การ
ลบ (DROP)
•Data dictionary
•Detailed description of all the data used in the database
